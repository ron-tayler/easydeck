# Сборка и публикация

## Что попадает в архив

Плагин — это архив `.easydeck`, внутри которого лежит:

```
plugin.json     манифест плюс поле main
main.mjs        всё, что плагин выполняет, одним файлом
assets/         картинки, на которые он ссылается
```

`main.mjs` собирается из исходников бандлером (в репозитории плагинов это
esbuild), так что внутри архива нет ни `node_modules`, ни шага установки.
`plugin.json` — это тот же манифест, что в коде, вынутый из собранного модуля,
плюс `main` с именем файла.

Расширение то же, что у профиля. Программа различает их по содержимому: архив с
`plugin.json` внутри — плагин.

## Что программа проверяет при установке

- **контрольную сумму** — до распаковки, а не после;
- **версию API** — точное совпадение с `PLUGIN_API_VERSION` этой сборки, иначе
  отказ с объяснением;
- **пути внутри архива** — файл, пытающийся распаковаться выше своей папки, не
  распакуется;
- **`main`** — он обязан лежать внутри папки плагина;
- **идентификатор** — два плагина с одинаковым `id` не уживаются, и программа
  скажет, какой из них уже стоит.

Распаковка идёт в отдельную папку и переименовывается на место, поэтому
прерванная установка не оставляет полуплагин. Удаление плагина **сохраняет его
настройки**: переустановка не требует заново вводить пароль.

## Каталог

Магазин — это два файла в релизе репозитория с плагинами:

- `<id>.easydeck` — сами плагины;
- `store.zip` — витрина: `index.json` со списком, манифест каждого плагина
  отдельным файлом и обложки.

Разделение здесь не случайное. Список должен быть лёгким — его читают, чтобы
показать пять строк; манифест и картинки подтягиваются, только когда человек
открыл конкретный плагин. Когда витрина была одним файлом с манифестами внутри,
на манифесты приходилось 97–99 % каждой записи.

`registry/index.json` в самом репозитории — тот же список, закоммиченный
сборкой. Его читает [страница плагинов](../../store/) на этом сайте.

Запись выглядит так:

```json
{
  "id": "ed.discord",
  "author": "ed",
  "version": "1.3.0",
  "apiVersion": 1,
  "file": "ed.discord.easydeck",
  "sha256": "3c3f2ff5…",
  "bytes": 31016,
  "name": { "en": "Discord", "ru": "Discord" },
  "description": { "en": "…", "ru": "…" },
  "cover": "plugin:ed.discord/assets/logo.webp"
}
```

## Своя папка вместо магазина

Для разработки программа умеет читать магазин из локальной папки — той, куда
сборка кладёт `build/`. Это включается переменной окружения; удобно, когда
плагин ещё не выпущен, а поставить его уже хочется.

## Свой репозиторий плагинов

Ничто не привязано к одному репозиторию. Источник магазина — это адрес, по
которому лежат `store.zip` и файлы плагинов; собственный набор плагинов
публикуется так же, как публикуется наш.

## Версия API

`PLUGIN_API_VERSION` меняется, когда ломается контракт. Программа сверяет её
точно: плагин, собранный под другую версию, не загрузится — и это осознанный
выбор в пользу внятного отказа вместо непонятной ошибки при нажатии клавиши.

Пока идёт ранняя разработка, версия будет меняться. Пересобрать плагин — это
`pnpm build` и новый релиз.
